# Data

The imported data were moved here without changing their bytes, names, or formats:

- `Data/`: 120 `.xls` files from `old_project/Data/`, named `V<speed>_Case<case>_CutFre<cutoff>.xls`. Observed speeds are 300, 350, and 380 km/h; cases are 1–8; cutoff labels are 20, 50, 100, 150, and 200 Hz.
- `data_old/`: three `.xlsx` files from `old_project/data_old/`, named `Patstitchcat_V<speed>icat557ipat1.xlsx`, one per speed. These are older data with a different column layout; they are preserved but not mixed into the main loader.

The previous paper describes a database generated by a validated numerical pantograph–catenary model. Do not label these files as field measurements without additional provenance. Experimental measurement data can also be stored locally here when available.

The `.xls` files contain one headerless four-column worksheet. The legacy code interprets columns as distance, acceleration, displacement (uplift), and contact force, in that order. The `.xlsx` files have headers `Distance [m]`, `Acceleration`, `Displacement`, `Force(20Hz)`, and `Force(raw)`.

All 123 spreadsheets were inspected and their SHA-256 hashes verified before and after migration. No missing or non-finite values were found in the parsed numerical data; distance increases within each file. Distance steps divided by the speed encoded in the filename imply approximately 0.001 s, assuming constant speed and the stated units. There is no explicit time column, so physical-time conversion still needs confirmation before PGND implementation.

The legacy reader uses `header=0`, consuming the first numeric `.xls` row as a header before trimming. The compatibility loader intentionally retains this behavior; correcting it changes sample counts/alignment and requires an explicitly revised protocol. No filter implementation or authoritative filter settings were supplied. The provided cutoff variants are used as-is; the representative 20/200 Hz comparison changes acceleration, displacement **and force**, while distance is unchanged.

All datasets remain local and ignored by Git; only this README is tracked. See [the migration audit](../legacy/README.md) for preprocessing and split limitations.
