# Data

The imported data were moved here without changing their bytes, names, or formats:

- `Data/`: 120 `.xls` files from `old_project/Data/`, named `V<speed>_Case<case>_CutFre<cutoff>.xls`. Observed speeds are 300, 350, and 380 km/h; cases are 1–8; cutoff labels are 20, 50, 100, 150, and 200 Hz.
- `data_old/`: three `.xlsx` files from `old_project/data_old/`, named `Patstitchcat_V<speed>icat557ipat1.xlsx`, one per speed. These are older data with a different column layout; they are preserved but not mixed into the main loader.

The previous paper describes a database generated by a validated numerical pantograph–catenary model. Do not label these files as field measurements without additional provenance. Experimental measurement data can also be stored locally here when available.

The `.xls` files contain one headerless four-column worksheet. The legacy code interprets columns as distance, acceleration, displacement (uplift), and contact force, in that order. The `.xlsx` files have headers `Distance [m]`, `Acceleration`, `Displacement`, `Force(20Hz)`, and `Force(raw)`.

Physical labels follow the source paper, *Real-time prediction of high-speed rail pantograph-catenary contact force using deep learning framework* (DOI: 10.1080/00423114.2025.2606345): Figure 7 (printed p. 13, PDF p. 14) explicitly labels acceleration in m/s², uplift in m, and distance in m. Figures 11–12 (printed p. 18, PDF p. 19) label contact force in N; the force-axis `[m]` in Figure 7 is an apparent typographical error and is not copied. The original reader maps these columns without unit conversion. These are the paper's simulation-unit conventions, not units inferred from numerical magnitude or independently supplied calibration metadata.

All 123 spreadsheets were inspected and their SHA-256 hashes verified before and after migration. No missing or non-finite values were found in the parsed numerical data. The canonical columns are **`distance, acceleration, uplift, force_N`**, with units m, m/s², m, and N, also recorded in `samples.attrs["units"]`. `distance` is exactly the first XLS column: no conversion, origin reset, rounding, or reconstruction from nominal spacing. The loader requires strictly increasing distance but does not require a uniform grid or discard nonuniform rows. There is no clock column and **no synthetic timestamp is created**; nominal speed remains filename metadata only.

`distance_spacing(recording.samples.distance)` gives the N−1 original spatial intervals in meters. The diagnostic report in `results/sampling_linear_seed0/raw_distance_spacing.csv` checks all 120 XLS files against native cell values and records mean, population standard deviation, minimum, maximum and median spacing per recording. Observation-spacing reports use actual retained coordinates on the existing trimmed CutFre20 segments; complete distance and force rows remain unchanged. The older time-coordinate verification records are historical evidence, not the current data contract.

The original Keras reader used `header=0`, consuming the first numeric `.xls` row as a header. The previously corrected `header=None` behavior is retained. The canonical loader now returns **all original rows** with recording identity and whole-case split membership: cases 1–4 train, 5–6 validation, 7–8 test, across all speeds/cutoffs. It performs no trimming, filtering, windowing or imputation. Explicit end trimming and next-sample windows are isolated in the baseline adapter; normalization uses training rows only. Details are in the root README.

No filter implementation or authoritative filter settings were supplied. The provided cutoff variants are used as-is; the representative 20/200 Hz comparison changes acceleration, displacement **and force**, while distance is unchanged. Upstream filtering causality remains unverified. Do not claim equivalence to unfiltered field measurements or mix cutoff variants as identical force truth.

All datasets remain local and ignored by Git; only this README is tracked. The three older XLSX files are preserved byte-for-byte as raw source data, not an active loader input. Removed exploratory code is recoverable from Git history.
